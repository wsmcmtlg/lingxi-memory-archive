## 二、编辑归档内容

用文本编辑器打开对应 md 文件，追加或修改内容。建议保持现有格式：

- 顶部保留 `> 归档日期：YYYY-MM-DD` 的引用块
- 用 `##` 二级标题分节
- 列表用 `-`，子项用两空格缩进
- 中文为主，内容可较详细（归档的意义就是保留细节）

## 四、git 提交并推送

打开 Git Bash，进入归档目录，依次执行：

```bash
cd "/c/Users/XBW/Documents/lingxi-claw/users/7022512/projects/11672630128672961/workspace/记忆归档"
```

### 1. 查看改动

```bash
git status
```
应看到被修改/新增的文件（绿色 `M` = 修改，`A` = 新增）。

### 2. 暂存（按需选择）

```bash
# 全部改动一起暂存
git add -A

# 或只暂存指定文件
git add "06_其他项目.md"
```

### 3. 提交（写清说明）

```bash
git commit -m "更新归档: <简短说明>"
```

例如：
```bash
git commit -m "更新归档: 新增供电所值班监控配置细节"
```

### 4. 推送到 GitHub

```bash
git push origin main
```

> 若未配置自动凭证，推送时会提示输入 GitHub 用户名与 PAT 令牌（Personal Access Token）。PAT 用完即删、不要写进任何配置文件。

### 5. 确认同步

```bash
git status -sb
git log --oneline origin/main -2
```

看到 `## main...origin/main`（无 ahead/behind 差异）即本地与云端一致。

## 五、常见问题

| 问题 | 解决 |
|------|------|
| `git push` 提示认证失败 | 需要有效 PAT，重新推送 |
| 想撤销某次未提交改动 | `git checkout -- <文件名>`（会丢失该文件未提交修改，慎用） |
| 想回滚最近一次提交 | `git reset --soft HEAD~1`（保留改动，重新提交） |
| 文件换行符提示 LF/CRLF | 正常，`.gitattributes` 已规范为 LF 入库，忽略即可 |
| 误把不该提交的文件加进去 | `git rm --cached <文件名>` 从暂存区移除，再编辑 `.gitignore` |

## 附：常用 git 速查

```bash
git add <文件>      # 暂存单个文件
git add -A          # 暂存全部
git commit -m "说明" # 提交
git push            # 推送到远程
git pull            # 拉取远程最新
git status          # 查看状态
git log --oneline   # 查看提交历史
```
