## 1. 牌具与字面

- 整幅 **112 张**：22 个字面 × 5 张 = 110 张 + 2 张赖子
- 字面 22 个：`上大人可知礼 化三千孔乙己 七十土 八九子 二四五六七八九十`
- 颜色：
  - 红牌（红）：上、大、人、可、知、礼、三、五、七、赖（10 字）
  - 黑牌（黑）：化、千、孔、乙、己、二、四、六、八、九、十、子、土（12 字）
- 精牌 7 字：三、五、七（红精）、乙、九（黑精）、赖（赖子，**只能通配三五七，不能当乙九**）
- 花/皮：精牌默认花（flower），非精牌默认皮（skin）；**花精胡数 ≥ 皮精，且花比皮翻倍**
- 显示映射：花三→叁、花五→伍、花七→柒、花乙→壹、花九→玖（大写，辨识度高）

## 3. 牌型体系

### 3.1 基础牌型（型牌）
| 牌型 | 构成 | 计胡 |
|------|------|------|
| 坎牌（kan） | 手中 3 张同字 | 红 2 / 黑 1 + 精牌逐张 |
| 顺子（seq） | 3 字合法顺子 | 红顺 1 / 黑 0 + 精牌逐张 |

### 3.2 扩展牌型
| 牌型 | 构成 | 来源 | 计胡基础 |
|------|------|------|---------|
| 碰牌（pen） | 手 2 + 旁家 1 | 旁家出牌 | 红 1 / 黑 0 + 精牌逐张（含精花+2皮+1主精翻倍） |
| 招牌（zhao） | 坎牌 + 旁家同字（明杠） | 旁家出牌 | 红 4 / 黑 2，精牌查 zhao 表 |
| 扎牌（zha） | 手 4 张同字（暗杠，含 3同+1赖） | 手中 | 红 4 / 黑 2，精牌查 zhao 表 |
| 穿牌（chuan） | 扎牌后摸到同字或赖通配 → 5 张 | 扎牌升级 | 红 8 / 黑 4，精牌查 chuan 表 |
| 泛牌（fan） | 扎牌+旁家出同字 / 招牌+摸同字 → 5 张 | 升级 | 红 8 / 黑 4，精牌查 chuan 表 |

### 3.3 眼（非型牌）
- **对子（眼）**：2 张同字；基础 0 胡；皮乙皮九 0 胡、皮三五七 1 胡、花精翻倍、主精再翻倍
- **口（半顺子）**：顺子中任意 2 张；也作眼；精牌逐张累加，主精 ×2

## 5. 胡牌条件

### 5.1 结构不变量
- **两听**：7 组型牌（基础+扩展）+ 2 眼（对子或半顺子）
- **摞听**：8 组型牌 + 2 眼
- 拆分以胡数最大为原则（最优拆分）
- 不以手中总牌数固定值判定，由拆分（_partition）自然判定

### 5.2 胡数门槛
- 最低 **17 胡**
- 拆分为胡数最大原则，_partition 深度优先：坎牌→含赖子坎→纯赖子坎→纯顺子→含赖子顺子

### 5.3 胡牌方式
- 自摸（额外奖励）
- 捉统：旁家打出的牌与手牌形成碰/顺满足胡牌条件，出牌者为"放统者"受罚；统牌算碰不算坎（已失自由度）

## 6. 计分（胡数→得分）

```
17-21 胡 → 3 分；每多 5 胡 +1（calcPoints = 3 + floor((hu-17)/5)）
```
- 旁家：从 2 起，每 5 胡 +1；放统旁家：从 3 起每 5 胡 +1；捉统：从 5 起每 5 胡 +2；自摸：从 6 起每 5 胡 +2

## 7. 主精规则
- 每局一个"主精"，由玩家按最大胡数原则确定
- 包含主精的牌型计胡 ×2
- 乙、九绝不可能作为主精
- 碰牌/口眼均计主精翻倍 ×2

## 9. ⚠️ JS 与 Python 双轨引擎差异（重点核对）

| 项目 | JS 版 `step5-hu.html` | Python 版 `melds.py` | 结论 |
|------|----------------------|----------------------|------|
| 固定顺子"孔乙己" | `['孔','乙','己']`（用"己"） | `("孔","乙","已")`（用"已"） | **不一致**，Python 疑似笔误 |
| 字面集合 | 22 字面含"己"、无"已" | CHAR_ATTRIBUTES 含"已"、无"己" | 与上同源不一致 |
| 数字顺子 | 8 种（含 `乙二三`） | 7 种（`NUMBER_CHARS` 从"二"起，**缺 `乙二三`**） | **Python 缺顺子** |
| 总顺子数 | 14 | 13 | Python 少 1 |
| 总牌数 | 112 | 112（create_deck 断言） | 一致 |
| 赖子通配 | WILD_USABLE=三五七 | WILD_TARGETS=三五七 | 一致 |
| 精牌 | RED_JING=三五七 / BLACK_JING=乙九 | 同 | 一致 |
| 花精显示 | FLOWER_DISPLAY 大写 | 无显示层 | 前端专属 |

> **调试提示**：若后期需将 Python 引擎作为测试基准，必须先修正"已/己"与"乙二三"差异；否则会与 JS 版产生规则判分偏差。JS 版（与规则文档一致）为准。

## 11. 防回归测试机制（改代码必跑）

> **目的**：避免为同类错误反复修改（穿牌花皮重分配、穿牌3皮2赖缺表等已发生过的坑），任何改动后一键验证不回归。

**一键入口**（在 `uploads/花牌游戏PWA (0808)/` 下）：
- Git Bash：`bash hu_tests/run_all.sh`
- Windows 双击：`hu_tests/run_all.bat`

**运行流程**：`hu_tests/extract_core.py` 用锚点从 `step5-hu.html` 提取核心规则引擎（不依赖行号，源码行号变化仍可提取）→ 依次运行 6 个测试。

**覆盖范围**：
| 脚本 | 覆盖 |
|------|------|
| `test_hu_tables_complete.js` | 红精+黑精 × 对/坎/扎/招/穿/泛 全部可达组合 39 项主精/非主精值 |
