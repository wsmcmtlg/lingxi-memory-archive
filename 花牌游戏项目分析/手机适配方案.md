## 三·五、移动端双击出牌修复（已完成，2026-08-29）

> 用户反馈：横屏问题解决后，**手机端双击牌出不了**。

### 根因

- 卡片只绑定了桌面 `dblclick` 事件（`el.addEventListener('dblclick', onDblClick)`），**触摸设备不产生 dblclick**，故手机双击无响应。
- 此前补丁脚本失败原因：`step5-hu.html` 为 **CRLF（\r\n）换行**，脚本用 `\n` 匹配 `onTouchDown` 文本失败。已改用正则（容忍 CRLF/LF）重写补丁。

### 方案（最小改动）

在 `onTouchDown`（touchstart）中加 **350ms 同一张牌双击检测**：

- 新增 `let lastTap = null;`（拖动变量声明旁）。
- `onTouchDown` 内：若 `!dragMoved && lastTap && lastTap.el===el && now-lastTap.time<350` → 清理拖动状态并 `playCard(el)`；否则记录 `lastTap={el,time:now}` 后照常 `beginDrag`。
- 语义与桌面 `onDblClick` 一致（检查 `G.locked`/`G.gameOver`），与长按放大（400ms）不冲突，双击（350ms）优先。

### 验证结果

| 项目 | 结果 |
|------|------|
| 单次触摸 | ✅ 仅记录 lastTap，不触发 playCard（spy=0） |
| 双击(150ms 内同一牌) | ✅ 触发 playCard（spy=1，lastTap 清空） |
| 真实双击端到端 | ✅ 手牌 26→25、locked=true（playCard 内 lockHand 生效） |
| 超时窗口(>350ms) | ✅ 不误触发（跨调用 17s 间隔验证） |
| JS 语法 | ✅ node --check 全部 script 块通过 |
| 计胡回归 | ✅ `hu_tests/run_all.sh` 6/6 通过 |
| 线上部署 | ✅ 已推送 main（commit ecb4875），GitHub Pages 构建 built，线上含 lastTap 修复 |

## 三·六、横屏下边家区域遮挡手牌修复（已完成，2026-08-30）

> 用户反馈：横屏实测中手牌区左侧前面约 5 张牌无法双击出牌。

### 根因

- 横屏断点下，边家手牌区/明牌区尺寸为 **120×260 / 80×260px**，`top:14%`（≈55px）向下延伸至 ~315px；庄家手牌区 `bottom:6px`（y≈266~384）。两者在 **y 266~315 重叠带**相交。
- 边家两区 `z-index:10`，`.hand-zone` 为 `auto(≈0)`，且边家区 `pointer-events:auto` → **触摸落在重叠区时命中边家容器而非庄家手牌** → `touchstart` 不到牌上 → 350ms 双击检测不触发 → 无法双击出牌。
- 几何计算（844×390）：左侧牌0、1被 side-hand-zone(left:12~132)遮挡，牌4、5被 side-meld-zone(left:170~250)遮挡；右侧牌16、17、20、21同样被遮挡（左右对称）。

### 方案（最小改动、不遮挡边家牌面）

横屏断点（`orientation: landscape and (max-height: 520px)`）下给 `.side-hand-zone` / `.side-meld-zone` 加 `pointer-events: none`。两块为纯展示区（牌背/明牌，无交互），触摸穿透到下方庄家手牌，边家牌面照常显示。

### 验证结果

| 项目 | 结果 |
|------|------|
| DOM 规则 | ✅ 横屏断点 `.side-hand-zone`/`.side-meld-zone` 均含 `pointer-events:none` |
| 穿透机制 | ✅ elementFromPoint：auto 命中 side-hand-zone（拦截）→ none 命中 card in-hand（穿透） |

## 三·九、手牌布局修正 + 暂存牌双击修复（已完成，2026-08-30）

> 用户反馈：手牌区个别地方（暂存区、中部、左部）双击出不了牌；局中有时候手牌靠下方排列，屏外牌无法操作。

### 根因

1. **`updateCardMetrics` 时序错误**：`initGame()` 第一行就调用 `updateCardMetrics()`，但此时 handZone 内还没有 `.card`（牌在 `layoutInitial` 的 `forEach` 才创建）→ 手机端（innerWidth≤1000）读不到真实尺寸，落到桌面默认值 `CARD_W=40/CARD_H=56/STEP_X=40`，而横屏实际卡片 `34×47`。
   - 后果：`perRow=19`（正确应为22）、`startY=-16`（第一行跑到手牌区上方 y=-16，被上方区域遮挡）→ 手牌局部溢出屏外/被遮挡、触摸命中异常 → 中部/左部/屏外牌无法操作。
2. **暂存牌（just-drawn）touchstart 无双击检测**：暂存牌绑定的 touchstart 是旧逻辑（只 `beginDrag`），没有手牌 `onTouchDown` 的 350ms 双击检测 → 暂存区双击出不了牌。

### 方案

| 改动 | 说明 |
|------|------|
| `updateCardMetrics` 加探针 | 手机端手牌未创建时，临时插入隐藏 `.card` 探针读取真实 CSS 尺寸（读后即移除），保证 `initGame` 首次调用即拿到 34×47 |
| 暂存牌 touchstart 加双击检测 | 与手牌 `onTouchDown` 完全一致：350ms 内同一牌第二次触摸 → 清理拖动状态 → `playCard(el)`；顺带修正 beginDrag 坐标用 `t.clientX`（原用 `ev.clientX` 对 TouchEvent 是 undefined） |

### 验证结果

| 项目 | 结果 |
|------|------|
| 手机横屏 metrics | ✅ 模拟 innerWidth=844 下 initGame 后 CARD_W=34/CARD_H=47/STEP_X=34（读真实尺寸） |
| 布局溢出 | ✅ 手牌无牌溢出 handZone（offCount=0） |
| 手牌双击 | ✅ 真实手牌双击出牌 spy=1 |
| 暂存牌双击 | ✅ 暂存牌双击出牌 playCalls=1 |
| 计胡回归 | ✅ `hu_tests/run_all.sh` 6/6 通过 |

## 三·十一、手机横屏弃牌池与明牌池重叠修复（已完成，2026-08-30）

> 用户反馈：手机端调试中弃牌池与庄家明牌池有重叠；建议弃牌池上移+加宽、明牌池下移。

### 根因

手机横屏（844×390）断点下：

| 牌池 | 原规则 | 纵向位置 |
|------|--------|----------|

## 四、适配目标与策略

1. **竖屏为主**（手持单手），**横屏支持**（对局观感更佳）——通过 `@media (orientation)` 双态。
2. **信息分级**：核心信息（余牌数、主精、回合、可操作提示）常驻顶部紧凑栏；次要信息（操作日志、完整状态）**折叠为可展开面板**，避免挤压。
3. **布局重排**：由"桌面绝对定位 + 顶部横排"改为"竖屏上中下三段分区"，杜绝重叠。
4. **触控友好**：主要按钮 ≥44px；禁双击缩放；防页面误滚动；保留长按看牌。
5. **安全区**：全面接入 `env(safe-area-inset-*)`，适配刘海/手势条。

## 五、分层实施方案

### A. 布局层（CSS，改 `step5-hu.html` 的 `@media(max-width:768px)` 段 + 新增竖屏段）

1. **顶部信息区重构（解决 #1 #2 #6）**
   - `z-game-status`：竖屏改为**顶部居中单行胶囊**（仅显示 `回合/主精/可操作`），完整状态（局数/阶段/副精/AI难度）点击展开浮层。
   - `z-deck`（余牌）：与状态栏同排，占左侧，字号缩小。
   - `log-bar`：改为**右上角折叠图标**（"☰日志"），点击弹出独立面板，不再常驻。
   - `player-info`：缩窄为仅"名称 + 关键统计"，各自贴近所属手牌（下家贴右下、上家贴左下、对家贴顶部），不与顶部栏重叠。
   - `sound-toggle`：移到状态栏右侧独立位置（避开牌面）。
   - `z-meld-bottom`：`width:500px` → `max-width: calc(100vw - 16px)`（解决 #6）。

2. **手牌区（解决 #3 #4）**
   - 手牌宽度改为 `calc((100vw - 左右安全边距 - 手指余量) / n)`，n 随 `@media(max-width:400px)` 取 14→15。
   - "庄家信息栏 + 篆体/图片按钮"整体**移到手牌区上方一条独立工具栏**，不覆盖手牌；或改为半透明贴边，保证手牌可见。
   - 手牌区 `bottom` 预留 safe-area。

3. **明牌区（解决 #5）**
   - 排查 `side-meld-zone` 在移动端未显示原因（疑似 z-index / 折叠 / 内容生成），竖屏改为紧凑横向排列在边家手牌内侧。

4. **安全区（解决 #7）**
   - 全局 `viewport-fit=cover` + `body{padding-bottom: env(safe-area-inset-bottom)}`，各 `bottom` 定位元素统一加 safe-area 偏移。

### B. 交互层（JS + CSS）

5. **触控目标（解决 #9）**：`.act-btn` 竖屏 `min-height:44px; min-width:44px`；`zha-pick-btn`、`lock-btn` 同步放大。
6. **防缩放/滚动（解决 #10）**：
   - `html,body{ touch-action: manipulation; }`（禁双击缩放）
   - `.table{ touch-action: none; }` 或 `overflow:hidden; position:fixed; inset:0` 锁死页面防回弹滚动。
7. **长按看牌优化**：保留 `card-zoomed`，缩短触发时长、放大时卡片不超出屏（`transform` 基于手牌中心）。
8. **弹窗适配**：`zha-pick-overlay`、`ting-popup`、`sound-settings-panel`、`stats-panel` 统一 `width:min(92vw, 420px); max-height:85vh; overflow:auto`。

### C. 横竖屏（CSS）

9. **竖屏** `@media (orientation: portrait) and (max-width:768px)`：采用上述重排布局（信息折叠、三段分区）。
10. **横屏** `@media (orientation: landscape) and (max-width:900px)`：沿用桌面横排，但顶部栏、边家、手牌按 vw 缩放到安全可用；开启 `screen.orientation.lock('landscape')`（可选，PWA standalone 下）。

### D. 性能（移动端）

11. 移动端降低 `backdrop-filter` 数量（低端机卡顿）、缩短/关闭常驻动画。
12. 手牌/牌面图片走 `cards/` 本地资源，避免移动网络加载。

### E. PWA 完善

13. `manifest.json`：`display:"standalone"`、`orientation:"portrait"`（或可选横竖）、`theme_color` 与背景一致。
14. viewport 增强：`content="width=device-width, initial-scale=1.0, viewport-fit=cover, maximum-scale=1, user-scalable=no"`。
15. iOS Safari：`-webkit-tap-highlight-color: transparent`；音频需用户手势后启动（已有点击解锁逻辑则复用）。
