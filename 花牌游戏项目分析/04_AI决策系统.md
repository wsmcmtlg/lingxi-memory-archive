## 1. 难度等级体系（JS 版）

| 等级 | 名称 | 说明 |
|------|------|------|
| 0 | 菜鸟 | 70% 随机 + 30% 基础启发式；碰牌全碰、扎牌全扎、不检测自摸 |
| 1 | 高手 | 基础启发式（张数/口子评分，保留赖子精牌）；自动碰/胡 |
| 2 | 大师 | 听牌感知出牌 + 完整胡牌检测 |
| 3 | 老千 | 完整记牌 + 深度听牌 + 攻防一体 + 行为识别 + 吃牌 |

## 2. JS 版 AI 决策函数地图

### 2.1 出牌总调度 `aiPickDiscard(hand, playerIdx)`（L7099）
按等级分发：L0/L1 → `_aiBasicDiscard`；L2 → `_aiSmartDiscard`；L3 → `_aiL3Cheat`

### 2.2 基础出牌 `_aiBasicDiscard`（L8018）
张数评分 + 口子评分 + 精牌加权

### 2.3 大师出牌 `_aiSmartDiscard`（L8051）—— L2
```
1. 预筛选 top-8 候选
2. 每张候选牌评分：
   - 基础保留价值（单张1/对子3/三张7/赖子50）
   - 记牌安全值（外部剩余少→安全）
   - 危险规避（getDangerScore）
   - 口连接度（半顺子伙伴）
   - 模拟打出后听牌状态
3. 综合评分 = 听牌奖励 + 安全值 − 危险惩罚
4. 听牌优先（1000 + maxHu×10 + tingCount）
```

### 2.4 老千出牌 `_aiL3Cheat`（L8157）—— L3
```
1. 预筛选候选 + 听牌检测（缓存版 _aiCalcTingInfoCached）
2. 外部可见度分析（弃牌池 + 旁家明牌）
3. 综合评分 = 听牌奖励 / 保留价值 / 记牌安全 / 危险惩罚 / 可见度
4. Phase 4 融入：三阶段感知 + 攻防模式 + 旁家行为分析 + 听牌后换听优化
5. 选出最佳出牌
```

## 7. 期望损失优化（Phase 7，2026-09-02）

> 用户需求：公安花牌是博弈游戏，攻防有讲究；最终目标是让自己多胡牌、别人少胡牌。因胡数要算分，实在不行就让胡数可能较少的玩家胡牌——"两害相权取其轻"。

### 7.1 新增 `_aiEstimateOpponentHu(pi)` 预期胡数估算（L8008）

- **明牌区**：`calcMeldHuTotal(pi)` 精牌查表精确计算（碰红1/黑0、穿泛查表等）
- **暗牌启发式**（常数级计数，不调 analyzeHand）：
  - 红精（三五七）每张 min+2 / max+4（坎查表5/10，对子眼1-2）
  - 黑精（乙九）每张 min+1 / max+3（坎1-3）
  - 赖子每张 min+2 / max+4（最少当花精+2，主精+4）
  - 坎牌（3张同字）红+2 / 黑+1
- 输出：`{meldHu, darkHuMin, darkHuMax, estHu, estPoints}`
- **estPoints（损失权重）**：estHu>=17 用计分阶梯（17-21→3、22-26→4、27-31→5…）；estHu<17 按比例 0~3（保持区分度，避免两家都=3分无法比较）
- 缓存 `_aiHuEstCache`：按手牌签名缓存，`_aiClearTingCache()` 同步清空

### 7.2 新增 `getRiskCost(ch)` 期望损失评分（L2570）

```
raw(ch) = Σ_{pi=1,2} max(听牌置信度, 行为置信度) × 稀缺度 × 手牌压力 × 过牌折扣 × estPoints(pi)
riskCost = min(1, raw / (3.0 × (estPoints1 + estPoints2)))
```

- 与 `getDangerScore`（对两家取 max）不同：**按各家预期胡数加权求和**，同一张牌喂给 20 胡的 A 家比喂给 5 胡的 B 家 cost 更高
- **归一化基准用两家 estPoints 之和**（上界：conf=1 × scarcity=2 × pressure=1.5 = 3.0），避免权重因子在分子分母相互抵消

### 7.3 L3 决策融合点（4 处）

| 位置 | 改动 |
|------|------|
| 非听牌评分 | `dangerPenalty = danger*20 + riskCost*30`（再乘攻防倍率） |
| 听牌候选评分 | `curScore = 实际听牌张数×30 + maxHu×15 − avgDanger×30 − avgRiskCost×25` |
| 阈值判断 | `(danger + riskCost×0.6) < dangerThreshold`（防守模式×1.0） |
| 兜底选牌 | 按 `danger + riskCost×0.6` 最小选择 |
| 预筛选 | `priority` 中危险项改为 `(danger + riskCost×0.5)` |

### 7.4 验证结果

- 新增单测 `test_ai_risk.js`（12 项断言，接入 run_all.sh）：
  - 场景A：明牌高胡家 estHu/estPoints 高于低胡家 ✅
  - 场景B：喂给高胡家的牌 riskCost > 喂给低胡家的牌（0.360 vs 0.240）✅
  - 场景C：estPoints 阶梯映射（17→3、22→4、27→5；空手=0）✅
- 回归 `run_all.sh` 7/7 全过（含既有计胡 6 项）
- 浏览器实测：注入 A 高胡/B 低胡场景，riskCost('上')=0.240 > riskCost('化')=0.160，"两害相权"生效
- L3 性能：实测平均 6.9ms / 最大 10ms（120ms 预算内）
- 已提交 main commit 40df873

### 7.5 显式止损模式（concede，2026-09-02，commit e78b7d8）

> 用户需求：现在 defend 模式只是把危险倍率调 2x，缺少"放弃胡牌、全力防守"的显式状态。加止损模式：牌差时宁可拆牌也要只打安全牌。

#### 触发条件 `_aiGetConcedeMode(playerIdx)`（三条件同时满足）

| 条件 | 判据 | 说明 |
|------|------|------|
| 自己牌力弱 | jingScore≤1.5 且 坎≤1 且 口≤2 | 精/赖少（赖×3、红精×1.5、黑精×1）、无坎、口子少 |
| 旁家威胁大 | 某家 estPoints≥3.5 | 复用 `_aiEstimateOpponentHu`，排除自己(playerIdx) |
| 晚局 | deckCount/总牌数 ≤45% | 余牌不多 |

#### 止损行为（L3 决策 5 处）

| 位置 | 改动 |
|------|------|
| 听牌分支 | 权重基数 10000→1000（不追求胡牌） |
| 听牌候选选择 | `&& !concedeMode.concede` 跳过（直接安全选牌） |
| 保留价值 | ×0.4（允许拆对子/坎） |
| 危险惩罚 | ×2.0 |
| 阈值 | 降至 0.25（只打绝对安全牌） |
| 兜底 | riskCost 权重 0.6→1.0 |

#### 验证

- 单测 `test_ai_concede.js` 14 项：场景A(弱+威胁+晚局→true)/B(强牌→false)/C(旁家无威胁→false)/D(余牌多→false)/E(边界 estPoints 3.5)
- 回归 `run_all.sh` 8/8 全过；浏览器实测止损场景 concede=true、对照 false；L3 性能 12.45ms

### 7.6 主动喂牌（Phase 7.6，2026-09-02，commit 69e4688）

> 用户需求（建议四）：止损模式下不能只是"自己不胡"，还应主动引导便宜家胡牌——"两害相权取其轻"的主动版本：宁可让胡数少的玩家胡，也别让危险家胡。

#### 目标识别 `_aiGetFeedTarget(playerIdx)`

仅止损模式（concede=true）下调用，返回 `{targetPi, dangerPi, targetPoints, dangerPoints, diff}` 或 null：

| 条件 | 判据 | 说明 |
|------|------|------|
| 只对两家旁家 | pi=1..2，排除自己 | 自己是出牌者，不能喂自己 |
| 便宜家须有潜力 | cheap.p > 0.5 | estPoints≈0 的家不值得喂（喂了也胡不了） |
| 分差明显 | diff ≥ 1.0 分 | 差距小不值得冒险喂 |

#### 分家评分 `_aiFeedScore(ch, feedTarget)`

对候选牌 ch 计算"喂送价值"（正=喂便宜家，负=喂危险家）：

| 来源 | 加权 | 说明 |
|------|------|------|
| 便宜家听牌需要 ch | +2×conf | guessOpponentTing + 行为推测 |
| 危险家听牌需要 ch | -3×conf | 重罚，绝不喂危险家 |
| 便宜家曾过此牌 | -1 | 过牌记录降权（她不要） |

#### L3 融合（4 处 + 2 修复）

| 位置 | 改动 |
|------|------|
| feedTarget 计算 | `concedeMode.concede ? _aiGetFeedTarget(playerIdx) : null` |
| 危险惩罚 | 喂牌目标牌（feedScore>0.5）dangerPenalty ×0.25——危险度主要来自便宜家自身听牌，喂送是止损本意 |
| 听牌分支 | 止损+喂牌时 `feedPriority` 让听牌候选走普通评分（已放弃胡牌，避免 1000 权重碾压喂牌信号） |
| 非听牌评分 | `discardPriority += feedScore * 30`（喂牌加分） |
| 阈值循环 | `feedAllow = min(1.5, 0.3+feedScore)`（喂牌目标牌阈值放宽） |
| 兜底 | feedScore 高者优先（同分取风险低） |

#### 验证

- 单测 `test_ai_feed.js` 10 项：场景A(差距明显→识别便宜家)/B(相近→不喂)/C(无潜力→不喂)/D(feedScore 分家：便宜家+1.6、危险家-2.4、中立0)/E(过牌降权)
- 回归 `run_all.sh` 9/9 全过；浏览器实测：止损场景 AI 优先打出便宜家需要的'上'（对照打安全牌）；L3 性能 avg 7.6ms / max 8.9ms（预算 120ms）

### 7.7 响应决策放铳成本（Phase 7.7，2026-09-02，commit 8102cad 已推送）

> 用户需求（建议五）：响应决策考虑放铳成本——碰/扎/招/吃后响应者必须立即打出一张牌，若手中无安全牌可打，响应反而制造放铳给危险家的机会，比不响应更糟。

| 函数 | 作用 |
|------|------|
| `_aiGetResponseThreat()` | 危险家判定：任一家旁家 estPoints>=3.5（与止损 oppThreat 同阈值），复用 `_aiHuEstCache` |
| `_aiForcedDiscardRisk(simHand, responderIdx)` | 遍历响应后手中可打牌（计数<=3），复用 getRiskCost 归一化公式，**排除响应者自己**（pi!==responderIdx，自己不会胡自己打出的牌），返回最安全牌 minRisk 0~1 |

参数：`RESP_SAFE_LINE=0.25`（无安全牌阈值）、`RESP_RISK_WEIGHT=30`（扣益系数，与 L3 riskCost*30 一致）。

- `_aiPenBenefit`：有危险家时碰后无安全牌（minRisk>0.25）返回 `reject` 一票否决；有安全牌则 `benefit -= minRisk*30`
- `_aiDecidePen`：reject 则直接返回 false 不碰

（注：本阶段只完成碰牌集成，招牌/吃牌/扎牌集成见 `06_Phase7.7_响应决策放铳成本_执行总结.md` 执行清单）

#### 验证

- 回归 `run_all.sh` 9/9 全过；语法检查通过

### 7.8 手牌降级排序修复（2026-09-08，commit 69dfc2e 已推送）

> 用户反馈：三参与固定顺子"化三千"，乙参与"孔乙己"。当手牌无化或千时，三仍按固定序排在二前（"三二四五"），无孔或己时乙仍排在二前（"乙三二四五"），不符合"乙二三四五"数字顺子习惯。

`getDynamicSortOrder` 两个 bug：

1. **降级条件误用 `&&`**：`!freeCounts['化'] && !freeCounts['千']`（化/千都缺才降级），改为 `||`（缺任一即降：组成固定顺子须两者同时在场）
2. **插入位置错误**：原乙和三都插在'二'前致"乙三二四五"，改为乙在二前、三在二后符合"乙二三四五"

场景验证：有千无化 / 有己无孔 / 乙三都降均正确；有化千/孔己时不降级。回归 run_all.sh 9/9 全过；浏览器实测四场景排序正确。注意 `getDynamicSortOrder` 读全局 `handCards`，返回排序串。

## 8. Python 版 AI（开发过程成果/04_AI模块）

### 7.1 体系
```
AI/
├── base.py        AIBase（抽象基类：decide_discard/decide_response/decide_self_action/decide_zha）
├── simple.py      SimpleAI（初学者：能胡就胡/能招就招/能对就对/能穿就穿/能吃就吃）
├── medium.py      MediumAI（听牌感知、选择性碰/吃、余牌感知）
├── controller.py  AIGameController（全自动 AI 对战 或 人机混合，HumanInputGate 阻塞等待）
└── tests/
hua-pai-game-ai/strategy.py   AIPlayer（Lv1~4 简化版：随机→基础→中级→高级，含记牌）
```

### 7.2 导入依赖（注意）
- `base.py` / `controller.py` 通过相对路径插入 `../Phase 1 规则引擎` 到 sys.path 以导入 core 包
- **⚠️ 当前目录树中不存在名为"Phase 1 规则引擎"的目录**（core 包实际在 `06_调试过程/hua-pai-game-core/`），直接运行 AI 模块可能因找不到 core 而失败；如需运行需调整 sys.path 指向 hua-pai-game-core

### 7.3 Python 对战控制器流程（controller.py）
`run_game → _run_one_round`：
```
反向扎牌阶段(_handle_zha_phase) → 庄家天胡 → 出牌(_handle_discard)
→ 响应(_handle_response, _resolve_responses 按距离/优先级) → 摸牌 → 自检 → 循环
```
- `DecisionLog`/`GameLog`：决策日志与汇总
- 支持 `seed` 固定随机、多局回归
