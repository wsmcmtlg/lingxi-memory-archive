# 2026-10-27 续：全荒庄根因修复 + 测量尺子突破

> 承接上节"下一步"：1、2（analyzeHandLoose + 听牌重定义）代码已接入但 30 局仍全荒庄。本节记录根因排除过程与最终修复。

## 5. 诊断过程（剥洋葱，共 5 层）

用 _d32~_d44 系列诊断脚本逐层定位（每层都先假设、再计数验证）：

1. **loose 链失效层**：57178 次 analyzeHandLoose 调用全部返回 null（structOK=0）。
2. **最小用例层**（_d33/_d34）：`上大人+乙乙` 这样最简单的"顺子+对眼"都 null；纯坎+对正常 → 顺子路径全断。
3. **根因①（沙箱保真度）**：`SEQ_BY_CHAR`/`ALL_KOU_LIST` 是**顶层裸语句**（for 循环+IIFE 构建），提取器只抓 var/function 声明 → 沙箱里顺子查找表全空 → 一切含顺子的拆分失败。修复：INJECT_TAIL 重建两表。**真实页面无此问题**（页面会执行这些语句），纯测量环境缺陷。
4. **根因②（harness 轮转）**：修表后仍 0/30。追踪发现庄家碰/招/捉铳分支只弹 UI 等人类点击 → harness 空队列直接摸牌跳过。旁家靠链式自动碰牌合并手牌（19~22 张）能到听牌，庄家永远 25+ 张散牌 → 102 回合 0 听牌。修复：空队列时 harness 庄家自动碰/招（复用页面 dealerPen/dealerZhao——注意须把二者加入 ROOT_FNS，否则 not defined 整局崩成 draw）。
5. **根因③（庄家手牌形态）**：页面 handCards 存 parseDeckCard 出的**卡牌对象**（含花/皮 v），harness 原来存裸字符串 → 捉铳 analyzeHand 静默失败。修复：对象化。自摸检测须传 preMelds（庄家明牌组的胡数）。
6. **根因④（最关键——AI 层字符串协议）**：`_aiBasicDiscard` 用 `for (const ch of hand)` 把元素直接当字——**页面 AI 层协议是字符串手牌**（旁家 hands 就是字符串）。harness 给庄家传对象 → `counts['[object Object]']` 全牌同桶 → 庄家每手都在弃固定位置，永不组织手牌 → 0 听牌。修复：`aiPickDiscard(handCards.map(c=>c.ch), 0)`。

## 6. 修复后基线（30 局，老千 vs 2×高手陪练，seed 20261027 批次）

- 胡牌终局 16 / 荒庄 14 / 异常 0
- 位0 老千：**20.0%**（6 胜）；位1/位2 高手陪练：13.3% / 20.0%
- 平均赢家胡数 21.6；庄家碰/招接管 57 次、捉铳成交 5 次
- 结论：**尺子量出真实信号了**。老千 20% 距目标 65%~85% 尚远，属正常——忍扎三问、§2.6 四规则、双向牌流、跨局建模均未实装，荒庄率 47% 也待压。

## 7. 方法论沉淀

- 同种子可复现（mulberry32 注入 Math.random）是逐层定位的前提——每次修复后同种子对照，差异即修复效果。
- "全荒庄"不是单一 bug，是 5 层缺陷叠加：沙箱缺失语句 → UI 等待断链 → 手牌形态错 → AI 协议错。任何一层修复后其它层继续挡路，必须计数探针逐层剥。
- 诊断脚本模式（_d3x 系列）：探针注入 INJECT_TAIL 之后 + 计数落盘（stdout 后台会丢）+ 签名比对区分"真实手牌"与"长度巧合"。
- 页面代码里**AI 函数（_aiBasicDiscard 等）只服务旁家**，协议是字符串；庄家（人类位）的 analyzeHand 用对象。两套协议并存，对接时必须显式转换。
